# Inline images are Kitty Unicode placeholders, fetched without credentials from GitHub's image hosts

The detail view's mini-map and the images in an issue body are shown with Kitty Unicode placeholders, not direct placements like the main map's. Each image is sent once, by ID, with a virtual placement (`U=1`), and the view prints placeholder cells (`U+10EEEE`, with row, column and ID high-byte diacritics on every cell) as ordinary text. So images scroll, and are repainted, with Bubble Tea's normal renderer, and need no placement to be recomputed on every scroll. Image IDs are 256-colour codes from 16 up, as Bubble Tea may downsample a truecolour ID and the low colours are remapped by themes. The main map keeps its direct placement (see [ADR 0002](0002-kitty-graphics-image-with-text-fallback.md)). Placeholders need the Kitty probe to pass, and are off in WezTerm, which passes it but can't show them, and with `--no-images`. Herdr redraws them on the outer terminal itself.

Body images are fetched by the app itself with Go's `net/http`, which makes it the one connection that isn't `gh`'s. Images in private repos load only from the signed `private-user-images.githubusercontent.com` URLs in the issue's `bodyHTML`, which expire after five minutes: the raw `user-attachments` URLs in the markdown return a sign-in page, even with a token. So the n-th image in the markdown takes the n-th `<img src>` in `bodyHTML`, and if the counts differ every image stays a `🖼 alt` placeholder. The fetch sends no credentials (no token, no cookies), and fetches only https URLs on `private-user-images.githubusercontent.com`, `user-images.githubusercontent.com` and `camo.githubusercontent.com`, redirects included. It has a 10 s timeout and a 10 MB cap, needs an `image/*` content type, and decodes only PNG, JPEG, GIF (first frame) and WebP images whose header says they are at most 4096 px either way. The signed URLs need no token, so none is sent, and the allowlist keeps an issue body from making the app fetch from anywhere else.

## Consequences

Anything else (another host, SVG, video, an oversized or undecodable image, a failed fetch) is a placeholder, and `o` opens the issue to see it. Images are fetched as soon as the issue arrives, before the signed URLs expire, and are cached by asset (the URL without its signature) for the session, so the poll doesn't fetch them again. An image whose fetch failed, as in a network blip, is fetched again on the next refresh, from its freshly signed URL; one that was fetched but can't be shown isn't, as it would be the same again. Leaving the detail view, moving to another issue and quitting delete the images by ID, as `Clear` doesn't remove virtual placements. The signed URLs aren't documented by GitHub; if they change, images fall back to placeholders and the rest of the view keeps working. Evidence: [Detail view: explore a ticket with its body, mini-map, images and relationships](https://github.com/distrail-io/wayfinder-map/issues/25).
